# IEP-P1-010 Firestore Security Rules

実装日: 2026-09-08

## 実装

- Firebase Authenticationだけでは業務データにアクセスできないようにした。`users/{uid}` に有効な `role`（`admin` または `member`）を持つ利用者だけがアクセスできる。
- `admin` はユーザー一覧の参照、利用者の作成、ロール変更、有効化・無効化を行える。自分自身を無効化・memberへ降格する操作と、物理削除は拒否する。
- `member` は自分のプロフィールだけを参照でき、業務データの登録・更新・論理削除・復元を行える。ユーザー管理、権限昇格、物理削除は拒否する。
- customersをsuppliersと同等に検証し、必須フィールド、型、文字数、作成日時の不変性、論理削除日時をRulesで確認する。
- products、rfqs、rfqItems、採番カウンターは既存の検証を維持し、採番カウンターには年形式、連番上限、連続増分の検証を追加した。
- 未定義のコレクション・サブコレクションは拒否する。
- Firestore EmulatorとRules統合テストを追加した。`npm run test:rules` は本番プロジェクトへ接続せず、`demo-ieppurchase-rules` を使用する。

## 初回適用手順

Rulesを本番へ反映する前に、Firebase ConsoleのFirestoreで最初の管理者を1件作成する。ドキュメントIDにはFirebase AuthenticationのUIDを使用する。

```text
users/{uid}
  email: <ログインメールアドレス>
  displayName: <表示名>
  role: admin
  active: true
  createdAt: <Firestore Timestamp>
  updatedAt: <Firestore Timestamp>
```

その後、同じ管理者でログインしてRulesを反映する。以降の利用者は管理者が同じ形式で追加し、roleを`admin`または`member`に設定する。`users`ドキュメントが未作成・無効・roleが不正なFirebase Authentication利用者は、ログインできても業務データへアクセスできない。

```powershell
npm run test:rules
npx firebase-tools deploy --only firestore:rules --project <Firebase Project ID>
```

## ブラウザ確認手順

1. Firebase Consoleで上記形式のadminユーザーを作成し、Rulesを反映する。
2. adminでログインし、顧客・仕入先・商品・RFQ・品目の既存操作ができることを確認する。
3. Firebase Authenticationには登録済みだが、`users/{uid}`がない利用者でログインし、各業務画面のデータ取得・登録がFirestoreの権限エラーで拒否されることを確認する。
4. `users/{uid}`の`active`をfalseにして再読み込みし、同じ利用者の業務データ操作が拒否されることを確認する。
5. memberユーザーでログインし、顧客・仕入先・商品・RFQ・品目を登録・編集できることと、Firestore Console以外からusersコレクションを作成・更新・削除できないことを確認する。
