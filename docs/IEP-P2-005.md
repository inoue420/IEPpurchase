# IEP-P2-005 EC購入候補の手入力・取得履歴保存

実装日: 2026-09-09。ユーザー動作確認待ち。

## 実装

- RFQ詳細へ「EC購入候補」を追加し、Amazon・楽天・その他の購入候補を手入力できるようにした。
- 保存先は `marketplaceOffers/{offerId}`。案件・RFQ品目・商品紐付け、購入先、外部商品ID、販売者、商品名、品番、数量、単価、送料、税区分、在庫、納期、URL、取得日時、備考を保持する。
- RFQ品目選択時に商品名・品番・必要数量を初期入力する。保存直前とFirestore Rulesの両方で、同一RFQの有効品目であることを確認する。
- 数量は0より大きく1,000,000以下、小数3桁まで。単価・送料は0以上の整数円。商品代と送料の税額を構成額ごとに切り捨てる。
- 送料未確認は `shippingFee`・集計金額を `null`、送料無料は `shippingFee: 0` として区別する。
- 候補は取得時点のSnapshotとして常に新規IDで追加し、既存候補の更新・物理削除を禁止する。同じ商品の新価格を追加しても旧価格を保持する。
- 外部APIによる自動取得、購入実行、購入実績への転記は対象外。

## ユーザー動作確認

1. `/rfqs` から品目が登録済みの案件を開く。
2. 画面下部の「EC購入候補」で「候補を登録」を押す。
3. 案件品目、購入先、商品名、数量、単価を入力する。
4. 送料を空欄にして保存し、一覧の送料と送料込総額が「未確認」になることを確認する。
5. 同じ商品をもう一度登録し、送料0円・異なる単価で保存する。
6. 新旧2件が両方残り、送料0円は「0円」、旧価格は変更されていないことを確認する。
7. Amazon・楽天・その他の候補、在庫、納期、http/httpsの商品URL、取得日時を保存し、再読込後も表示されることを確認する。
8. 数量0・小数4桁、負の価格、http/https以外のURLが保存できないことを確認する。
