# IEP-P3-001 freee連携アプリ登録・OAuth認証準備

## 状態

ユーザー作業待ち。freeeの連携アプリ登録および対象事業所でのOAuth認可は、freee管理権限を持つユーザーが実施する。

## 登録時の設定

freee開発者ページの「アプリ管理」からOAuthアプリケーションを作成し、以下を設定する。

| 項目 | 設定 |
| --- | --- |
| アプリ名 | IEPpurchase（社内資材調達管理） |
| 用途 | 社内利用（外部公開はしない） |
| 連携対象 | freee請求書の見積書連携（将来の実装時に限定して使用） |
| コールバックURL | 次タスクで実装・公開するIEPpurchase所有のHTTPS URL |
| アクセス権 | 見積書連携に必要な最小権限のみ。不要な会計・人事労務権限は付与しない。 |

公開済みのコールバック受信エンドポイントはまだないため、仮URLや `urn:ietf:wg:oauth:2.0:oob` を本番設定に使用しない。freee公式仕様では、ローカルテスト以外に自社所有HTTPS URLを指定することが求められている。

## 実施手順（freee管理者）

1. [freee Developers Community のアプリケーション作成手順](https://developer.freee.co.jp/startguide/starting-api)から、freeeアプリストアの開発者ページを開く。
2. OAuthアプリケーションを作成し、上記の基本情報と最小権限を設定する。
3. 発行されたClient IDを確認する。Client Secret、認可コード、アクセストークン、リフレッシュトークンは、管理シート・チャット・Gitに貼り付けない。
4. 実装するコールバックURLが確定した後、そのURLをfreee側の基本設定に登録する。
5. 次タスクの接続画面から認可を開始し、対象事業所を選択して許可する。認可時には `state` を照合し、`prompt=select_company` を使って対象事業所を明示選択する。

## Secretの保管方針

- Client Secret、アクセストークン、リフレッシュトークンはサーバー側のSecret管理にのみ保管する。
- ブラウザの環境変数、Firestore、ソースコード、Git履歴には保存しない。
- アクセストークンは6時間、リフレッシュトークンは90日が有効期間で、リフレッシュトークンは1回限り使用可能。更新時には新しいトークンを直ちに置き換える。

## 完了条件

freee連携アプリの登録、必要最小権限の設定、対象事業所でのOAuth認可準備が完了していること。見積書の本番作成・送付はこのタスクに含めない。
