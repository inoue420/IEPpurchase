# IEP-P3-004 販売見積基盤・freeeへの翻訳明細転記

実装日: 2026-09-14。ユーザー確認OK・完了。ローカル実装・自動確認済み、ユーザー確認待ち。Firestore Rules、Functions、Hostingは本番反映済み。freeeへの実登録は未実施。

## 対象と保存方式

- ユーザーの「基盤も実装しましょう」により、販売見積ヘッダー、販売単価、税計算、保存版、freee新規作成を追加。
- P3-003で確定した `salesQuotes/{rfqId}/items` をサーバーで読み、原文・登録英訳・確定出力文・品番・数量・単位を保存版に取り込む。後日のRFQ変更を反映せず、転記時の再翻訳も行わない。
- `salesQuotes/{rfqId}/freeeExports/current` に現行の販売見積・送信状態を保存。配下の `revisions/{revision}` に入力、金額、原文・訳文、freeeペイロードを不変保存し、`events` に日時・利用者・版・結果を追記する。
- 通常のクライアント書き込みはRulesで拒否。Callable Functionsだけが検証・計算して更新する。保存時はexpectedRevision、送信時はrevisionとdigestで同時編集・古いプレビューを拒否する。

## 金額と入力

- JPY。数量・販売単価は小数3桁まで。販売単価0〜10億円、数量99999999.999以下、合計1兆円以下、1〜100明細。
- 販売単価は利用者入力。仕入価格から勝手に転記しない。
- 税別／税込、税率0・8・8軽減・10%、明細金額と消費税それぞれの切り捨て／四捨五入／切り上げに対応。
- 十進数を整数化してBigIntで計算。明細金額を丸め、税率・軽減税率区分ごとに税額を計算する。初期値は税別10%、切り捨て。画面とサーバーで同じ計算モデルを使用。
- freee摘要は `品番 + 改行 + 確定出力文`（品番が空の場合は出力文のみ）。255文字を超えた場合は切り詰めず登録を拒否。改行はJSON文字列のまま送る。
- 出力文が空なら拒否。登録英訳なし、または出力文の日本語文字を検出した場合は警告し、利用者の翻訳確認を必須にする。言語検出は補助的な文字種チェックであり、翻訳品質を保証するものではない。
- P3-003の確定済み出力文を編集・再確定する機能は変更していない。長すぎる確定文は送信できず、短い出力文の別見積を準備する必要がある。
- freee取引先IDは既存の顧客IDを手動指定。先頭ゼロを含む正の整数も保存時に受け付け、freee送信時は数値として渡す。確認ダイアログでRFQ顧客名・接続事業所ID・取引先ID・全明細・合計を確認する。顧客マスターとfreee取引先の自動同期は未追加。

## 外部送信と復旧

1. 「販売見積を保存」はFirestoreへの保存のみ。freeeへ見積は作成しない。
2. 「freeeへの登録内容を確認」で保存版のプレビューを表示する。
3. 「確認した内容でfreeeに登録」で明示確認した版だけを `POST https://api.freee.co.jp/iv/quotations` へ送信する。顧客へのメール送付は行わない。
4. Firestoreトランザクションで `draft / failed → sending` を確保する。同時送信や送信済み再要求は追加POSTしない。
5. HTTP 400/401/403/404/422/429の明示拒否は `failed` とし、修正・再認可後の利用者による再試行を可能にする。
6. 通信断・タイムアウト・5xx・不正な成功応答は `uncertain` として再作成を停止する。外部作成成功後にFirestore保存が失敗した場合も `sending` のまま再作成を停止する。
7. 送信開始から2分後、作成済みfreee見積書IDを利用者が入力しGETで照合する。事業所、取引先、ID、送信版固有の社内メモが一致する見積だけを紐付ける。自動再POSTはしない。見つからない場合は管理者の調査が必要で、利用者による強制解除は提供しない。
8. freeeの明細・金額と送信内容を比較し、差異や未取得項目がある場合は `needs_review` を保存して画面で帳票確認を促す。作成済みIDは保持し再作成しない。

保存履歴と操作履歴は画面に最新20版／20件を表示し、過去の保存版を開ける。表示範囲外もFirestoreに保持する。
