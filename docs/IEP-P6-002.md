# IEP-P6-002 AI・OCR・翻訳サービスの認証準備

## 状態

ユーザー作業待ち。採用するAI、OCR、翻訳サービスの選定、および各サービスの契約・支払設定・API認証情報の発行は、契約権限を持つユーザーが実施する。

このタスクは認証準備だけを対象とする。AI/OCR/翻訳の本体実装、外部サービスへの業務データ送信、本番運用の開始は含めない。

## 実施前の決定

サービスの登録やAPIキー発行を始める前に、次の内容を決定する。

| 対象 | 決定する内容 |
| --- | --- |
| AI | 採用サービス、用途、利用モデル、月額予算、月間上限 |
| OCR | 採用サービス、入力形式、想定月間ページ数、月額予算、月間上限 |
| 翻訳 | 採用サービス、対象言語、想定文字数、月額予算、月間上限 |

- 無料枠、従量課金、保存先・学習利用の扱い、国内外へのデータ送信条件を、契約前に各サービスの公式資料で確認する。
- 課金の有効化、予算を超える利用枠の設定、業務データを用いる接続試験は、ユーザーの明示承認後に行う。
- サービス未選定の段階では、特定サービスのAPIキーを取得しない。

## ユーザー実施手順（採用サービス決定後）

1. 採用した各サービスについて、組織または業務用アカウントを作成する。個人アカウントと共有しない。
2. プロジェクトまたはアプリケーションを作成し、用途を「IEPpurchaseの社内資材調達業務」に限定する。
3. 最小権限のサービスアカウント、APIキー、OAuthクライアントなど、採用方式に必要な認証情報だけを発行する。
4. 月額予算、使用量アラート、ハード上限（提供される場合）を設定する。上限値と設定日だけを管理シートへ記録する。
5. 認証情報の値はチャット、Google Drive、管理シート、ソースコード、`.env`、Gitに記載せず、安全な受け渡し方法で担当者に共有する。
6. 接続実装時に、Firebase Secret ManagerへSecretを設定する。Secret名、設定日、設定担当だけを記録し、Secret値は記録しない。
7. 最小権限の接続確認後、不要なテスト用キーを失効または削除する。

## Secretの保管方針

- APIキー、クライアントシークレット、サービスアカウント秘密鍵、OAuthトークンはFirebase Secret Managerだけで扱う。
- Firestore、Cloud Functionsのソースコード、ブラウザの環境変数、ログ、エラー通知、Git履歴には保存しない。
- Secretを利用するCloud Functionsだけに、必要なSecretの参照権限を与える。人・環境・機能ごとに共通キーを使い回さない。
- 漏えいの疑いがある認証情報は直ちに失効し、新しいSecretバージョンへ差し替える。

## 管理シートへの記録

Secret値やアカウントIDは記録しない。次の事実だけを残す。

- 採用サービス名と用途
- 認証方式（APIキー、サービスアカウント、OAuthなど）
- 利用上限・予算の設定済み可否
- Secret設定済み可否と設定日
- 接続準備の確認結果

## 完了条件

採用サービスが決まり、必要な登録・最小権限の認証設定・利用上限および予算設定が完了し、認証情報を安全にサーバー側Secret管理へ設定できる準備が整っていること。
