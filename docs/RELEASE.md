# リリースとバージョン表示

## 普段の公開手順

VS Codeで変更をコミットし、「変更の同期」を完了する。そのコミットへタグを付けてからビルドする。
各コマンドが成功したことを確認してから次へ進む。build失敗時には既存のdistを公開しない。

```powershell
git tag v1.0.1
git push origin v1.0.1
npm run build
npx firebase deploy --only hosting --project ieppurchase
```

- リリースごとに2か所のタグ番号を変更する。VS CodeのコミットメッセージとGitタグは別であり、メッセージだけでは表示に反映しない。
- `v1.0.0`、`v1.0.1`などのタグを使用する。軽量タグ・注釈付きタグの両方に対応する。
- 公開済みタグは付け替えない。自動表示の実装前に作成したv1.0.0は保持し、今回の実装を含む新しいコミットにはv1.0.1などを付ける。
- VS Codeの同期後にも変更が入った場合は、先に再度コミット・同期する。タグに未コミット変更は含まれない。
- Hosting以外のFunctions、Firestore/Storage Rules、indexesを変更した場合は、該当部分も別途検証・デプロイする。
- デプロイ成功後に利用者へ、入力内容を保存してからページを再読み込みするよう案内する。

## 画面表示

ログイン後の共通アカウント欄で、メールアドレスの下に`バージョン v1.0.1`を表示する。
Viteの起動・ビルド時にローカルのGit情報を読み取り、文字列を埋め込む。ブラウザからGitやGitHubへのアクセスは行わない。

- タグが付いたコミットで未コミット変更がない: `v1.0.1`
- タグ以降のコミットがある: `v1.0.1-1-gabcdef0（開発版）`
- 変更・未追跡ファイルがある: `v1.0.1-dirty（開発版）`など。Gitで無視されているdist・node_modules・環境設定は判定対象外。
- リリースタグがない: コミットの短縮IDと`（開発版）`
- Git情報を取得できない: `開発版（バージョン不明）`

通常のdev・buildは開発版でも利用できる。公開前に正式タグの表示を確認する。
タグを作成するだけでは既存distや公開済み画面は変わらない。必ずタグ作成後に再ビルドする。
開発サーバーの起動中にタグを変更した場合は、サーバーを再起動する。

## 過去版の取り出し

未コミット変更のない状態で、過去タグを起点に確認用のブランチを作る。

```powershell
git switch -c codex/restore-v1.0.1 v1.0.1
```

タグが保存するのはコミットされたソースと設定・依存関係のlockファイル。Firestoreデータ・秘密情報・公開済み成果物は別管理。
過去ソースの再公開には、環境設定・依存関係およびFunctions・Rules・現在データとの互換性を確認する。
