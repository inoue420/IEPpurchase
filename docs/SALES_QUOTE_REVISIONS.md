# 販売見積の改訂とfreeeへの再転記

2026-10-14：ユーザーの1案採用により実装。ローカル実装・自動確認・本番反映済み／完了・ユーザー確認OK。

## 動作

- 案件番号は維持する。「改訂版を作成して編集」で現在の明細・価格を引き継ぎ、明細を再確定してから新しい販売見積保存版を作成する。
- freee転記前の下書き・登録拒否も、保存済み明細の編集を開始できる。
- 前回の見積を顧客へ未提示なら、前回のfreee見積書IDにPUTする。新規POSTはしない。同じ見積書番号・取引先を保持する。
- 顧客へ提示済みなら、旧freee見積書を残してPOSTで改訂見積を作成する。案件番号は維持し、freee見積書は1件増える。手動採番の場合は新しい見積書番号を入力する。
- 提示有無は選択必須。freee外でメールやPDFを渡した場合も提示済みとする。保存と最終転記確認でも上書き／新規を表示する。
- 数量・品番・品目追加／削除はRFQ品目を編集し、改訂開始後に「RFQ品目を再取り込み」で反映する。出力文の上書きは従来の再取り込みダイアログで確認する。既存明細の価格・送料・マージン・税率はIDで引き継ぎ、新規明細だけ初期値を使用する。

## 保護と履歴

- 改訂開始は`startSalesQuoteRevision` Callableのトランザクションだけが実行する。認証・元の版番号／digest・RFQ状態・翻訳明細の確定状態を照合する。同時改訂は一方だけ成功する。
- 改訂開始時にサーバー管理の`editing`を設定し、翻訳明細を下書きへ戻す。Rulesはこの許可を確認し、通常クライアントからの許可偽造や送信中の編集を拒否する。送信処理は編集中の古い保存版を受け付けない。
- 過去の`revisions`を書き換えず、原文・英訳・出力文・数量・販売価格・金額を保持する。`events`へ改訂開始／転記方式／成功ID・番号を記録し、前回の転記結果も保持する。
- `lastSentRevision`で転記成功の事実を保持し、改訂中や改訂の転記拒否で案件一覧を「見積取得済」に戻さない。
- 上書き時は既存帳票をGETし、事業所・見積書ID・番号・社内メモ・前回の明細／金額／ヘッダーを照合する。新しい転記結果には帳票内容のdigestも保存し、次回はテンプレート・宛先・担当者等を含めて照合する。既存の旧結果でdigestがない場合も送信済みpayloadと金額を照合する。
- freeeで送付済み／取消済み／送付状態不明、手修正による不一致、GET失敗ではPUTを行わない。更新対象が存在しなくてもPOSTに切り替えない。テンプレート・住所・担当者等のAPI対応フィールドは取得内容を更新リクエストへ引き継ぐ。
- 送信中・結果不明は編集も再転記も停止する。PUTの結果不明は元のIDと新版の社内メモでGET照合する。旧メモや別IDでは照合を成功としない。転記成功後のFirestore記録失敗でも同じ制限を維持する。

freee APIにはこの実装が利用できる条件付き更新の仕組みがないため、GET照合後からPUTまでの間のfreee画面での同時編集を完全には防げない。転記中は同じ帳票をfreee画面から同時編集しない。上書きしたfreee帳票のリンクは最新版を表示する。旧内容はシステムの保存履歴に保持し、顧客に渡した旧帳票自体を残す場合は「提示済み」で新規作成する。
